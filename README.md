# Decision OS｜互動式隨機決策系統

> **資訊工程系特殊選才作品展示** · HTML / CSS / JavaScript · Canvas 2D · Web Audio API · localStorage

**Decision OS** 是一個以瀏覽器執行的單頁互動工具，提供「選項隨機抽選」及「指定上限的隨機整數產生」兩種模式。介面採用科幻雷達、文字解碼與視覺粒子動畫，並結合音效、色彩主題及本機設定保存。

這個作品主要展示 **前端程式設計、事件處理、資料狀態管理、動畫與基本安全意識**；它是獨立的小型網頁專案，與其他作品不需共同安裝。

## 主要功能

| 功能 | 實作方式 |
| --- | --- |
| TARGETS 隨機選項 | 使用者輸入選項後，以 `Math.random()` 搭配陣列索引選出一個項目 |
| 三組選項清單 | `SLOT A / B / C` 可切換，選項及設定儲存於瀏覽器 `localStorage` |
| NUMERIC 隨機數字 | 依使用者設定的正整數上限，產生 `1` 至上限之間的整數 |
| 雷達與背景動畫 | 使用 Canvas 2D、CSS 動畫、`requestAnimationFrame()` 繪製動態視覺效果 |
| 互動回饋 | Web Audio API 產生合成音效，裝置支援時可使用震動 API |
| 個人化設定 | 四種視覺主題、動畫速度、靜音設定 |

## 技術架構

```text
瀏覽器 UI（HTML / CSS）
     │ 使用者點擊、輸入、切換模式
     ▼
JavaScript 事件與狀態管理
     ├── 選項資料：allSlots / currentSlot ── localStorage
     ├── 選項抽選：Math.random() + 陣列索引
     ├── 整數抽選：Math.random() + 數值範圍
     ├── Canvas 背景 / 雷達動畫 ── requestAnimationFrame
     └── 音效 / 震動回饋 ── Web Audio API / Vibration API
```

本專案**沒有伺服器端程式、帳號系統或雲端資料庫**。選項與偏好會保存在當前瀏覽器與網站來源的本機儲存空間中。

## 可解釋的程式設計重點

### 1. 從使用者輸入到選項集合

以陣列表示三個獨立儲存槽，切換 `currentSlot` 決定目前顯示及抽選的選項。新增、刪除或清空選項時，同步更新清單、雷達顯示與本機儲存資料。重新開啟頁面時嘗試還原先前選項。

### 2. 抽選邏輯與動畫分離

TARGETS 模式先決定抽選結果，再顯示旋轉、減速與結果揭示動畫；NUMERIC 模式則在指定數字區間產生整數。動畫是**視覺呈現**，不是決定結果的物理模擬。程式使用 `Math.random()`，適合一般休閒決策，不適合需要可稽核亂數、公平性保證或密碼學安全的用途。

### 3. 前端安全與輸入檢查

公開前曾對程式做基本安全整理：

- 清單文字使用 `textContent` 和 DOM 節點建立，避免把使用者輸入直接當作 HTML 解譯。
- 從 `localStorage` 讀取資料時檢查 JSON 結構；對已儲存的選項進行型別與長度限制。
- 每個選項槽最多保留 100 個選項，每個選項最多 100 字元。
- 限制動畫速度設定範圍，並檢查主題名稱。

這些只是基本改善，**不代表完成全面資安稽核**。目前 Google Fonts 字型資源仍需連向外部網站，介面與無障礙支援亦有改善空間。

## 使用方式

1. 下載本儲存庫中的 `index.html`，直接使用瀏覽器開啟；也可以透過 GitHub Pages 開啟網站。
2. 在 **TARGETS** 頁面輸入至少兩個選項，點擊 **ADD** 加入，再按中央 **ENGAGE** 抽選。
3. 點選 **SLOT A / B / C** 可使用不同選項清單。
4. 在 **NUMERIC** 頁面設定數字上限，按 **ROLL** 產生隨機整數。
5. 可切換顏色主題、速度與音效；資料只保存在目前瀏覽器的本機儲存空間。

> **GitHub Pages**：儲存庫開啟 `Settings → Pages → Deploy from a branch → main / (root)` 後，網站可在 `https://jerryyang2.github.io/decision-os/` 瀏覽（以實際部署結果為準）。

## 專題學習與後續改善

這個作品讓我能從單一檔案觀察使用者輸入、陣列狀態、DOM 更新及動畫的互動。相較於單純寫出隨機數公式，更值得進一步理解的是「切換資料組時如何保持正確狀態」、「如何避免字串輸入形成注入風險」，以及「瀏覽器儲存資料壞掉時如何降級處理」。

未來可以擴充：

- 增加自動化 UI 測試，檢查切換儲存槽、刪除選項與重新載入的行為。
- 改善鍵盤操作、色彩對比、行動裝置縮放與其他無障礙細節。
- 讓輸入數字的最大範圍及錯誤提示更完整。
- 將 HTML、CSS、JavaScript 拆分，降低單一檔案維護難度。
